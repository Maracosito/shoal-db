La pregunta
Desarrollar un clon/alternativa de código abierto, completamente nuevo y legalmente independiente, inspirado en Turbopuffer: una base de datos de búsqueda vectorial y de texto completo nativa para almacenamiento de objetos, destinada a aplicaciones de IA/RAG.

Restricciones legales y de producto importantes:
No copie el código fuente, la implementación privada, la marca, el logotipo, el diseño del sitio web, los textos, los nombres, la imagen comercial, los activos propietarios ni la documentación exacta de Turbopuffer. Debe ser una implementación completamente nueva con marca, interfaz de usuario y documentación originales, y su propio diseño de API cuando corresponda. Utilice Turbopuffer únicamente como inspiración para productos públicos: almacenamiento de objetos como fuente de información fiable, computación sin estado, almacenamiento en caché SSD/memoria, espacios de nombres, búsqueda vectorial, búsqueda de texto completo, búsqueda híbrida, filtros de metadatos y ramificación de espacios de nombres.

Nombre provisional:
Utilice un nombre original provisional como "OpenPuffer" o elija un nombre de proyecto mejor y legalmente distinto durante la planificación.

Meta:
Crea un motor de búsqueda de código abierto con calidad de producción que los desarrolladores puedan ejecutar localmente o implementar en la nube. Debe admitir almacenamiento en frío económico en almacenamiento de objetos compatible con S3, consultas rápidas en caliente mediante cachés de disco y memoria locales, y una API HTTP intuitiva para desarrolladores, además de clientes para Python y TypeScript.

Requisitos básicos:

1. Arquitectura
- El estado persistente reside en el almacenamiento de objetos: almacenamiento compatible con S3, MinIO para desarrollo local y modo de sistema de archivos local para pruebas.
- Los nodos de cómputo deben ser lo más independientes del estado posible.
- Utilice un diseño de almacenamiento por espacio de nombres con manifiestos, archivos de registro de escritura anticipada, archivos de índice, archivos de metadatos y referencias de ramas.
- Separar el procesamiento de consultas de la indexación/compactación en segundo plano siempre que sea posible.
- Proporcionar un documento de arquitectura claro que explique el formato de almacenamiento, la ruta de consulta, la ruta de escritura, el modelo de consistencia y las ventajas e inconvenientes.

2. Servidor API
- Crear una API HTTP JSON con autenticación mediante claves API.
- Dar soporte a organizaciones/proyectos/espacios de nombres.
- Los espacios de nombres son espacios de documentos aislados.
- Los documentos tienen identificadores, vectores densos opcionales, vectores dispersos opcionales, campos de texto y atributos de metadatos arbitrarios.
- Incluir puntos finales para:
  - crear/actualizar/eliminar espacio de nombres
  - metadatos del espacio de nombres
  - actualizar/insertar documentos
  - documentos de parche
  - eliminar por ID
  - eliminar por filtro
  - consulta
  - exportar espacio de nombres
  - copiar espacio de nombres
  - espacio de nombres de rama
  - caché caliente / espacio de nombres de anclaje
  - Control de salud y métricas

3. Escribir ruta
- Implementar el registro de escritura anticipada persistente en el almacenamiento de objetos.
- Admite actualizaciones e inserciones por lotes.
- Admitir la ingesta de documentos orientados a filas y a columnas, si es factible.
- Admitir escrituras idempotentes siempre que sea posible.
- Admite escrituras condicionales básicas.
- Implementar la indexación en segundo plano después de las escrituras.
- Implementar la compactación para que muchos archivos WAL/índice pequeños puedan fusionarse en segmentos consultables eficientes.
- Asegurar que las escrituras exitosas sean recuperables después del reinicio del proceso.

4. Ruta de consulta
- Admite la búsqueda de vectores densos:
  - Línea base kNN exacta
  - Índice aproximado del vecino más cercano adecuado para la recuperación respaldada por almacenamiento de objetos, preferiblemente de estilo IVF/centroide en lugar de un índice gráfico basado únicamente en memoria.
  - coseno, producto escalar y distancia euclidiana
- Admite la búsqueda de texto completo:
  - tokenización
  - índice invertido
  - Clasificación BM25
  - ponderación o refuerzo del campo
- Admite búsqueda híbrida:
  - Combinar los resultados del vector y del BM25
  - Admite la fusión de puntuaciones ponderadas y la fusión de rangos recíprocos.
  - permitir solicitudes de múltiples consultas
- Admitir la búsqueda de vectores dispersos si es factible.
- Admite filtros de metadatos:
  - Eq, NotEq, Gt, Gte, Lt, Lte, In, ContainsAny
  - Y, o, no
  - Coincidencia de cadenas cuando sea posible
- Admite la devolución únicamente de los atributos seleccionados.
- Admite top_k / límite.
- Incluir un planificador de consultas que permita elegir entre búsqueda exacta, redes neuronales artificiales (ANN), índice de texto completo, índice de filtros y rutas de ejecución híbridas.

5. Indexación
- Crear archivos de índice persistentes almacenados en el almacenamiento de objetos.
- Crear segmentos de índice almacenables en caché local.
- Incluir índices de filtros/atributos para una búsqueda filtrada rápida.
- Incluir un manifiesto de metadatos de índice.
- Incluir comandos de reconstrucción y reparación.
- Incluir pruebas que demuestren que los índices sobreviven a los reinicios y que pueden reconstruirse a partir del almacenamiento de objetos.

6. Jerarquía de caché
- Implementar una caché de disco local para los espacios de nombres o segmentos consultados recientemente.
- Implementar una caché de memoria para los elementos de metadatos/índices de uso frecuente.
- Utilice LRU o un sistema de desalojo configurable.
- Agregar un punto final de caché en caliente que precargue un espacio de nombres o segmentos seleccionados.
- Añadir la opción de fijar espacios de nombres para que los espacios de nombres seleccionados se mantengan activos.
- Comparar el comportamiento de las consultas en frío con el de las consultas en caliente.

7. Ramificación de espacios de nombres
- Implementar la ramificación de espacios de nombres con copia en escritura.
- La ramificación debería crear rápidamente un nuevo espacio de nombres haciendo referencia a archivos/segmentos inmutables existentes.
- Las escrituras en la rama no deberían afectar al código fuente.
- Las escrituras en el código fuente no deberían afectar a la rama.
- Al eliminar una rama, no se deben eliminar los datos de origen compartidos que aún estén referenciados.
- Incluir pruebas para el aislamiento de ramas, ramas multinivel, eliminación de ramas y consulta de ramas.

8. Constancia y recuperación
- Documentar claramente las garantías de consistencia.
- Como mínimo, proporcione escrituras persistentes y un comportamiento de lectura de escrituras en una implementación de nodo único.
- Para el modo distribuido/multinodo, documente claramente cualquier posible compromiso en cuanto a la consistencia.
- Incluir pruebas de recuperación tras fallos:
  - Reiniciar después de escribir
  - Reiniciar durante la indexación
  - Reiniciar durante la compactación
  - Manejo de archivos corruptos/incompletos cuando sea posible

9. Experiencia del desarrollador
- Proporcionar una interfaz de línea de comandos (CLI) para:
  - Iniciando servicios de desarrollo local
  - creación de espacios de nombres
  - Carga de datos JSON/JSONL/CSV
  - ejecutar consultas
  - Exportación de datos
  - caché de calentamiento
  - evaluación comparativa
- Proporcionar el SDK de Python.
- Proporcionar un SDK para TypeScript/JavaScript.
- Proporcionar Docker Compose con servidor API, worker/indexer, MinIO y una aplicación de ejemplo.
- Proporcionar manifiestos de Kubernetes o gráficos de Helm opcionales.
- Proporcionar la especificación OpenAPI.

10. Aplicaciones de demostración
- Crea al menos tres demos:
  - Demostración de búsqueda semántica de documentos/RAG
  - Demostración de búsqueda híbrida sobre texto + incrustaciones
  - Demostración de búsqueda de código que utiliza ramificación de espacios de nombres para representar diferentes ramas o espacios de trabajo.
- Incluir conjuntos de datos de ejemplo lo suficientemente pequeños como para poder ejecutarlos localmente.
- Incluir scripts para generar incrustaciones utilizando un proveedor de incrustaciones conectable, pero la base de datos en sí no debe depender de ningún proveedor de incrustaciones en particular.

11. Observabilidad y operaciones
- Añadir registros estructurados.
- Añadir métricas de Prometheus.
- Si es posible, añada ganchos de rastreo básicos o instrumentación de OpenTelemetry.
- Incluir métricas para la latencia de las consultas, aciertos de caché fríos/calientes, retraso de indexación, lecturas/escrituras de almacenamiento de objetos, tamaño del WAL, recuento de segmentos y estado de compactación.
- Añadir límites de velocidad y cuotas como configuración opcional.
- Agregar registros de auditoría para el espacio de nombres y las operaciones de escritura.

12. Seguridad
- Autenticación mediante clave API.
- Evite registrar información confidencial.
- Modelo a seguir básico, si es posible: administrador, escritor, lector.
- Documentación opcional sobre cifrado en reposo mediante el cifrado del proveedor de almacenamiento de objetos.
- Documentar el modelo de amenazas y las directrices para el endurecimiento de la implementación.

13. Pruebas y evaluación comparativa
- Pruebas unitarias para almacenamiento, API, filtros, clasificación, matemáticas vectoriales, BM25, ramificación, almacenamiento en caché y recuperación.
- Pruebas de integración utilizando MinIO.
- Pruebas de extremo a extremo a través de los clientes Python y TypeScript.
- Conjunto de pruebas de referencia que mide:
  - rendimiento de ingesta
  - latencia de consulta en frío
  - latencia de consulta en caliente
  - recall@k para ANN frente a kNN exacto
  - Latencia BM25
  - latencia de consulta híbrida
  - Tasas de aciertos de caché
- Incluya resultados de referencia realistas pero honestos. No afirme que es igual a Turbopuffer a menos que lo demuestre.

14. Documentación
- Archivo README con guía de inicio rápido.
- Guía de arquitectura.
- Referencia de la API.
- Documentación del SDK de Python.
- Documentación del SDK de TypeScript.
